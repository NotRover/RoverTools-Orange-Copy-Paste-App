A space code is one string, eight characters, good for 72 hours, and it cannot be rotated. Today holding it makes you a member. After this, it gets you a knock at the door and somebody inside answers — and answering is what finally hands you the key.

The change, in one gesture

The code stops being the authorisation

Right now one string does two jobs: it introduces you to a space, and it authorises you to be in it. Every leak is a silent join because those two jobs are the same click. Split them and the leak becomes a knock.

Was

A member instantly, readable eventually. The owner learns about it by noticing a new name.

Now

One extra step, and the step is the one that hands over the key. You arrive able to read, not able to wait.

Correction

Keys were never in the mail

Worth being exact, because it changes what the fix has to be. A Space Key is wrapped X25519-to-X25519 between two apps; the server relays a blob it cannot open, and a mailbox never holds one. What the invite email carries is the code.

That does not make the concern wrong, it makes it precise: the code is a multi-use bearer capability — about 240, one per space, no rotate route — and join_space turns it into a membership with no gate at all. A forwarded mail, a screenshot in a group chat, a stale link in someone's history: each is a join nobody approved.

Who may answer the door

One control, and it is the only one

On the space, owner's choice: owner only, or owner and any member. New spaces start owner-only. There is no second switch, no per-invite setting, and no expiring-code option — approval is what rotation was for.

No new role either. role is already 'owner' | 'member', and a boolean grants exactly the one capability asked for. Rename, delete and remove-member stay the owner's, because removing a member forces a rekey and that is not a capability to hand out in passing.

What this does not fix

The code still cannot be rotated

One code per space, 72 hours, no rotate route. Rotating would break every link already sent. Approval is the mitigation: a leaked code buys a knock, not entry.

A leaked code invites knocking

Strangers can now raise requests where before they simply walked in. Capped at one row per person per space, and a declined row is kept precisely so the same code cannot produce a second knock.

Owner-only spaces can still stall

If the owner never opens the app, a request sits. That is strictly better than today, where the joiner sits in the same silence already — but flipping the member switch on is the fix, and it is one line in the space's settings.

Nothing is revoked retroactively

Anyone who joined by code before this ships is a member and stays one. Approval gates the door, not the room.
